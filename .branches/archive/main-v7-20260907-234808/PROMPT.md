# 分支候选规则（branches/task-style-v2/PROMPT.md）

> 本文件是分支 task-style-v2 的候选规则，仅在本分支试跑期间生效。
> 实验目的：写法改进 + A-F六条题目条款 + 只交FCStd，快速出结果。

## 1. 任务定位

生成 FreeCAD 1.1.3 版本参数化建模题目，配套对应验收核对清单（Checklist）。整体风格简洁、考点明确，避免非考点冗余内容。

## 2. 输入与产出

- 输入形态：用户指定模型主题或由 AI 自选简单基础几何体
- 产出物及格式：
  1. 一份完整的 FreeCAD 建模任务题目（Markdown 文本）
  2. 一份严格对应题目的验收核对清单（```plaintext 代码块包裹）

## 3. 长期提示词 / 工作规则

### 3.1 题目必含条款（信息必达，表述自由）

以下条款必须出现在题目中，但**组织方式、措辞、段落顺序均可灵活变化**，禁止每题套用同一模板：

#### A. 环境一行前置信息
必须写明：FreeCAD 1.1.3 安装路径（freecadcmd.exe 与 freecad.exe 同目录）、用户宏目录已配置为脚本存放目录、脚本存该目录、模型存桌面 freecad 文件夹。

#### B. 几何口径无歧义定义
- "对边距"指明为内切圆直径（=2×边心距），不是轮廓 Y 向总宽；多边形朝向写明（如"平边朝 +Y 即一条边水平且位于 +Y 侧"）
- 可附参考量：边心距、外接圆半径、边长、顶点极角
- 盲孔深度自顶面名义面向下量
- 圆角/倒角对象精确指定（如"仅顶面与侧立面交线，孔口边、侧棱不倒"）

#### C. GUI 执行通道
- GUI 中先 Ctrl+N 新建文档使宏菜单可用，再经"宏 (M)→宏…→选中脚本→执行"运行一次
- 禁止走 Python 控制台粘贴/键入（粘贴不稳定）
- 脚本负责自建文档、存盘，并在末尾把 Body 的 ViewObject 设为可见、执行一次视图 FitAll，避免界面空白

#### D. 草图约束策略
- 约束方式不限，允许按精确计算坐标放置几何后用 Block 约束整体锁位
- 要求全约束、单闭合线框
- 不强制"构造圆 + 等长"类参数化约束

#### E. 验收口径与理论值（定义正确性，不要求提交验收产物）
题目必须给出可验证的验收口径和理论值，至少覆盖：
- 单一 Body / 单一实体
- 特征 TypeId 白名单（Sketcher::SketchObject、PartDesign::Pad/Pocket/Fillet 等），禁 Part 造体与布尔
- 关键水平截面形状与面积（用 Part.Face(wire).Area）
- 几何参数理论值（边长、内角、边心距、孔壁半径、孔深范围等）
- 特征面数量与参数（如圆柱面数量、半径、轴线位置、高度）
- 理论体积（带容差，如 1%）
具体数值因题而异，但每题必须给出。

#### F. 调试纪律
- 建模脚本要求零求解器告警（告警即换约束方案，同一方案最多试两次）
- 若使用验收脚本，异常与结论必须同时写日志文件落盘，不得只依赖控制台输出

#### 其他必含信息
- **标题**：含"FreeCAD建模任务"和模型名称
- **任务说明**：一两句话说清要建什么
- **环境准备**：先结束所有残留 FreeCAD 进程，再全新启动 → Part Design 工作台 → 检查桌面 freecad 文件夹
- **脚本与调试解耦**：脚本编写和 freecadcmd 无头调试可先行；GUI 仅执行一次最终脚本
- **脚本存放与兜底**：脚本统一放宏目录；写入被拒排查一次仍不行则暂存桌面 freecad 文件夹并注明
- **模型约束**：Part Design 原生特征、同一 Body、单一实体、禁止 Part 模块直生几何体、禁止布尔拼接
- **尺寸参数**：XY 平面基准、+Z 拉伸、Z=0 底面；主体 + 核心特征 + 棱边处理；特征 2-3 个；数值明确
- **文件覆盖**：同名 FCStd 直接覆盖，不另存版本号
- **操作准则**：单卡点最多两种思路，第一种两次失败即切换；报错先找根因再整体重跑
- **只建模不验收**：题目定义验收口径但不要求提交验收脚本/报告；建模脚本跑完存盘即完成
- **交付标准**：仅提交 FCStd 文件，存桌面 freecad 文件夹；不提交脚本、验收报告等额外产物

#### 表述自由度
- 不必每次都用固定的二级标题，可自由组织
- 可以把相关信息合并成一段，也可以拆开
- 开篇说明可以换说法
- 核心是信息到位、读起来像人写的

### 3.2 语言风格（去AI味）

- **说人话**：自然口语化书面表达，避免AI套话
- **不堆排比**：不要每条都用相同句式开头
- **不写正确的废话**：删掉无信息量的句子
- **长短句交错**：适当用短句、断句
- **每题换说法**：同一信息点在不同题目中用不同措辞

### 3.3 题目间低一致性（硬性要求）

- **模型类型不重复**：不得连续两题用同类型主体
- **特征组合不重复**：核心特征类型和棱边处理要换
- **尺寸量级有差异**：适当拉开大小差异
- **结构组织不重复**：二级标题、段落顺序、信息合并方式每题不同
- **开篇和措辞不重复**：句式、用词每题换
- **Checklist 话术不重复**：开头词、句式、表达角度全部不同
- **自检**：出完与最近 3 题对比，至少 4 项不同

### 3.4 验收核对清单（Checklist）硬性规则

Checklist 是简化版 Rubric，用于确认模型"做没做、做没做对、做没做好"。一条可同时校验若干紧密相关点，但必须覆盖所有关键验收点。

#### 三层校验框架
- **做没做**：模型是否执行了题目明确要求的任务
- **做没做对**：模型是否正确完成各项要求，事实类验收点尽可能完整列出
- **做没做好**：质量是否达到要求

#### 硬规则
1. **表述可判定**：每条均能由题目、产物判定，避免空话
2. **非动作指令**：不使用"检查、查看、核对、浏览"等词；改写成可判定的陈述或问题
3. **与评分说明一致**：信息足以判定，不能只写几个字
4. **完整/相关/相对独立**：关键点不漏、无题外项、条目间尽量不重叠
5. **条目总数 5-6 条**：按维度合并实现，不得遗漏核心要求
6. **话术多变**：每条开头词和句式不同，题目间也不重复
7. **格式**：用 ```plaintext 代码块包裹，条目编号清晰

#### 输出前自检维度
| 维度 | 是否必须有对应条目 |
|------|-------------------|
| 交付物文件存在、命名正确、路径正确 | 必须 |
| 文件可正常打开、无损坏 | 必须 |
| 题目中每个功能点/操作步骤 | 必须 |
| 题目中每个量化参数 | 必须 |
| 题目中的格式/命名/路径要求 | 必须 |
| 题目中的"不要…"类约束 | 必须 |
| 题目未提及的额外要求 | 禁止 |

## 4. 风格与质量标准

- 简洁、考点明确，避免非考点冗余内容
- 建模难度简单级，特征 2-3 个
- 尺寸数值明确、几何口径无歧义
- Checklist 可判定，总数 5-6 条，话术多变
- 语言自然，无AI套话和模板感
- 题目间低一致性
- 题目含 A-F 全部条款，验收口径与理论值给死
- 只建模不验收，交付仅 FCStd 文件，快速出结果

## 5. 例外与边界

### 负面禁止项
- 不得新增题目未要求的验收标准
- 不得出现主观模糊描述
- 不得遗漏题目明确的交付与约束要求
- 不得使用复杂结构模型
- Checklist 不得超过 6 条或少于 5 条
- 不得使用AI套话、排比堆砌、正确的废话
- 不得每题套用完全相同的标题结构和措辞
- Checklist 各条不得使用相同开头词或固定句式
- Checklist 不得使用动作指令开头
- Checklist 不得遗漏"文件可正常打开、无损坏"
- Checklist 不得有题外项
- 不得连续两题使用同类型主体几何体
- 不得连续两题使用相同的核心特征类型
- 不得把脚本编写/无头调试与 GUI 初始化绑成硬门
- 不得在目录不可写时卡死
- 不得使用"全新启动"而不说明残留进程处理
- 多边形不得不标朝向
- 盲孔不得不写平底/钻尖类型
- 倒角/圆角不得不指定棱边范围
- 不得要求提交验收脚本或验收报告
- 不得走 Python 控制台粘贴执行脚本
- 建模脚本不得有求解器告警
