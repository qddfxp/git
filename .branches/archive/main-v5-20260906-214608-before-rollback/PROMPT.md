> 本文件是分支 task-style-v2 的候选规则，仅在本分支试跑期间生效。
> 实验目的：8条写法改进——GUI与脚本解耦、目录兜底、进程清理、多边形朝向、盲孔类型、棱边范围、独立验收脚本、保留卡点规则。

## 1. 任务定位

生成 FreeCAD 1.1.3 版本参数化建模题目，配套对应验收核对清单（Checklist）。整体风格简洁、考点明确，避免非考点冗余内容。

## 2. 输入与产出

- 输入形态：用户指定模型主题或由 AI 自选简单基础几何体
- 产出物及格式：
  1. 一份完整的 FreeCAD 建模任务题目（Markdown 文本）
  2. 一份严格对应题目的验收核对清单（```plaintext 代码块包裹）

## 3. 长期提示词 / 工作规则

### 3.1 题目内容要求（信息必达，表述自由）

以下信息点必须出现在题目中，但**组织方式、措辞、段落顺序均可灵活变化**，禁止每题套用同一模板：

#### 必含信息点
- **标题**：含"FreeCAD建模任务"和模型名称，格式不必每次相同
- **任务说明**：用一两句话说清要建什么
- **环境准备**：先检查并结束所有残留 FreeCAD 进程，再全新启动 FreeCAD 1.1.3 → 处理弹窗 → Part Design 工作台 → 检查桌面 freecad 文件夹（不存在则新建）
- **脚本与调试解耦**：脚本编写和 freecadcmd 无头调试可先行，不必等 GUI；GUI 初始化后仅执行一次最终脚本，不在 GUI 里反复调试
- **脚本存放与兜底**：脚本统一放 `E:\jiaobenmulu`；若写入被拒，排查一次仍不行则暂存桌面 freecad 文件夹并注明，不卡死
- **模型约束**：Part Design 原生特征、同一 Body、单一实体、禁止 Part 模块直生几何体、禁止布尔拼接
- **尺寸参数**：XY 平面基准、+Z 拉伸、Z=0 底面；主体尺寸 + 核心特征尺寸 + 棱边处理（倒角/圆角）；特征 2-3 个；数值明确、定位清晰
- **多边形朝向**：使用正多边形时必须指定朝向（如"平边朝上""尖角朝右"），不得只给尺寸不标朝向
- **孔类型明确**：盲孔必须写明"平底盲孔"或指定钻尖角（如 118°）；通孔、沉孔等也写明类型
- **棱边范围封死**：倒角/圆角必须明确指定哪些棱（如"仅外轮廓六条棱，孔口棱不倒"），不得有歧义
- **文件覆盖**：同名 FCStd 文件直接覆盖，不另存版本号
- **操作准则**：单卡点最多两种思路，第一种两次失败即切换；报错先找根因再整体重跑
- **交付标准**：英文文件名.FCStd → 桌面 freecad 文件夹 → 交付绝对路径 + 模型树特征排列顺序
- **独立验收脚本**：建模脚本只负责建模 + 存盘，不写合格判定；另需一个独立验收脚本，从磁盘重新打开 FCStd 回读，按 Checklist 逐项输出验收结论

#### 表述自由度
- 不必每次都用固定的二级标题，可自由组织
- 可以把相关信息合并成一段，也可以拆开
- 开篇说明可以换说法
- 核心是信息到位、读起来像人写的，而不是填表

### 3.2 语言风格（去AI味）

- **说人话**：用自然口语化的书面表达，避免AI套话
- **不堆排比**：不要每条都用相同句式开头
- **不写正确的废话**：删掉无信息量的句子
- **长短句交错**：避免全是结构工整的长句
- **每题换说法**：同一信息点在不同题目中用不同措辞表达

### 3.3 题目间低一致性（硬性要求）

每道新题必须与已产出的所有题目保持**低一致性**：

- **模型类型不重复**：主体几何体类型交替使用，不得连续两题用同类型主体
- **特征组合不重复**：核心特征类型要换，棱边处理也要换
- **尺寸量级有差异**：适当拉开大小差异
- **结构组织不重复**：二级标题名称、段落顺序、信息合并方式每题不同
- **开篇和措辞不重复**：任务说明的句式、用词每题换
- **Checklist 话术不重复**：各题 Checklist 的开头词、句式、表达角度全部不同
- **自检**：出完新题后，与最近 3 道题对比，确认至少有 4 项不同

### 3.4 验收核对清单（Checklist）硬性规则

Checklist 是简化版 Rubric，用于确认模型"做没做、做没做对、做没做好"。一条可同时校验若干紧密相关点，不要求为了原子化无限拆分；但必须覆盖所有关键验收点。

#### 三层校验框架（构思时用）
- **做没做（要求执行情况）**：模型是否执行了题目明确要求的任务，关键要求逐项覆盖，不遗漏核心任务
- **做没做对（事实准确性）**：模型是否正确完成各项要求；需外部核验的事实补充可靠外验链接及结论；事实类验收点尽可能完整列出
- **做没做好（产物质量）**：在完成任务的前提下，质量是否达到要求

#### 硬规则
1. **表述可判定**：每条均能由题目、产物或公开来源判定，避免"质量高""看起来专业"等空话。
2. **非动作指令**：不使用"检查、查看、核对、浏览"等命令模型执行动作的词；改写成可判定的陈述或问题。
3. **与评分说明一致**：通过/不通过的判定基于本条 Checklist，信息足以判定，不能只写几个字。
4. **链接可用**：需外验的事实附真实、可打开、无需验证码或受限登录的链接。
5. **完整/相关/相对独立**：关键点不漏、无题外项、条目之间尽量不重叠。
6. **条目总数 5-6 条**：通过按维度合并实现，不得通过遗漏核心要求凑数。
7. **话术多变**：每条开头词和句式不同，题目间也不重复。
8. **格式**：用 ```plaintext 代码块包裹，条目编号清晰。

#### 输出前自检维度（逐条对照题目，确认全覆盖）
| 维度 | 是否必须有对应条目 |
|------|-------------------|
| 交付物文件存在、命名正确、路径正确 | 必须 |
| 文件可正常打开、无损坏 | 必须 |
| 题目中每个功能点/操作步骤 | 必须 |
| 题目中每个量化参数（尺寸、数量、角度等） | 必须 |
| 题目中的格式/命名/路径要求 | 必须 |
| 题目中的"不要修改/不要删除"类约束 | 必须 |
| 题目未提及的额外要求 | 禁止（无题外项） |

## 4. 风格与质量标准

- 简洁、考点明确，避免非考点冗余内容
- 建模难度控制为简单级，特征数量 2-3 个
- 尺寸数值明确、定位关系清晰
- Checklist 条目可客观判定，总数 5-6 条，话术多变
- 语言自然，无AI套话和模板感
- 题目间低一致性
- 无歧义：多边形朝向、孔类型、棱边范围均明确
- 建模与验收分离：独立验收脚本从磁盘回读验证

## 5. 例外与边界

### 负面禁止项
- 不得新增题目未要求的验收标准
- 不得出现主观模糊描述
- 不得遗漏题目明确的交付与约束要求
- 不得使用复杂结构模型，控制建模难度为简单级
- Checklist 不得超过 6 条或少于 5 条
- 不得使用AI套话、排比堆砌、正确的废话
- 不得每题套用完全相同的标题结构和措辞
- Checklist 各条不得使用相同开头词或固定句式套路
- Checklist 不得使用动作指令开头（检查/查看/核对/浏览等祈使动词）
- Checklist 不得出现不可判定的空话（质量高/看起来专业等）
- Checklist 不得遗漏"文件可正常打开、无损坏"这一必检项
- Checklist 不得有题外项（题目未提及的额外要求）
- 不得连续两题使用同类型主体几何体
- 不得连续两题使用相同的核心特征类型
- 不得把脚本编写/无头调试与 GUI 初始化绑成硬门
- 不得在目录不可写时卡死，必须有兜底
- 不得使用"全新启动"而不说明残留进程处理
- 多边形不得只给尺寸不标朝向
- 盲孔不得不写平底/钻尖类型
- 倒角/圆角不得不指定棱边范围
- 建模脚本不得包含合格判定，验收必须独立脚本从磁盘回读
