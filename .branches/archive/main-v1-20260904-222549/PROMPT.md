## 3. 长期提示词 / 工作规则

### 3.1 题目固定结构与内容要求

#### 标题与开篇
- 标题格式：`FreeCAD建模任务：XXX`
- 开篇说明：`请使用 FreeCAD 完成 XX 的参数化建模，模型生成后直接保存文件即可，无需额外开展尺寸核对、特征校验类操作，精简执行流程。`

#### 执行要求（固定模块，可按需微调表述）
必须包含以下 4 项，表述统一：
1. **前置准备**：全新启动 FreeCAD 1.1.3 客户端，处理弹窗至主界面稳定运行，切换至 Part Design 工作台；检查桌面 freecad 存储文件夹，不存在则新建。准备就绪后输出 "GUI 环境初始化完成"，在此之前不得编写任何建模脚本或创建代码文件。
2. **脚本规范**：建模所用 Python 脚本统一存放至 `E:\jiaobenmulu` 目录，禁止写入软件安装路径或系统目录；API 属性调用以 1.1.3 版本为准。
3. **效率提示**：支持无头预验证模式，可先通过 freecadcmd 完成脚本逻辑调试，GUI 仅执行一次最终脚本即可，无需界面反复调试。
4. **模型约束**：最终实体必须为 Part Design 工作台下的原生参数化特征，全部特征归属同一 Body 并自动融合为单一实体；禁止使用 Part 模块直接生成几何体，也不允许通过布尔运算拼接模型。

#### 尺寸参数
- 模型选择简单易建模的基础几何体，特征数量控制在 2-3 个，避免复杂结构
- 明确基准：默认以 XY 平面为草图基准，+Z 为拉伸方向，Z=0 平面为模型底面
- 所有尺寸标注明确数值，定位关系清晰（如 "中心同轴""居中对齐"），无模糊描述
- 包含：主体尺寸 + 核心特征尺寸 + 棱边处理（倒角 / 圆角，二选一或组合均可）

#### 操作准则（固定规则）
单个卡点最多构思两种解决思路，第一种方案尝试两次仍无法推进则立刻切换第二种，不重复已验证失败的路径；脚本报错先定位根本原因，修正后整体重跑，不逐行补丁式调试。

#### 交付标准
必须包含 3 项：
1. **文件命名**：英文文件名.FCStd
2. **存储位置**：桌面 freecad 文件夹
3. **交付内容**：文件完整绝对路径 + 模型树特征排列顺序

### 3.2 验收核对清单（Checklist）硬性规则

1. **严格对应题目内容，禁止加题外项**：所有验收条目必须 100% 来自题目明确给出的要求、参数、约束，不得新增题目未提及的判定标准（如禁止出现 "无尖锐棱边残留" 等主观描述）。
2. **单条单事实，可客观判定**：每条仅包含一个可独立验证的事实，附带明确数值 / 状态判据，无模糊、主观表述。
3. **全覆盖无遗漏**：必须覆盖题目所有核心要求，包括：主体尺寸、核心特征尺寸、棱边处理参数、模型合规性（同一 Body、单一实体、Part Design 原生特征）、文件交付（命名、存储路径）、交付内容要求。
4. **条目独立**：各验收项之间无重叠、无包含，每条可单独判定通过 / 不通过。
5. **格式**：用 ```plaintext 代码块包裹，条目编号清晰。
